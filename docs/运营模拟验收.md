# 企微分层工作台运营模拟验收

2026-11-13。按单人高中课程运营的工作顺序验收。原生工作台使用独立副本和本地 SQLite，会话均为合成数据。采集环节将合成窗口快照送入原生工作台调用的同一个后台入口，分层使用本机 Ollama `qwen3:4b`，同步写入独立的真实飞书数据表。

## 优先处理的问题

| 优先级 | 复现与实际结果 | 对运营的影响 |
| --- | --- | --- |
| 高 | 客户说「我在南京市，我高二，选科是政史地，数学月考72分，函数题容易丢分，预算有限」。用户基本情况记录了函数丢分，学习目标为空，有效线索判定和当前阶段均为「待识别」。 | 明确表达了学习困难的高中生会从有效线索名单漏掉。 |
| 高 | 运营说「明天晚上7点可以试听」，客户说「好，就约这个时间」。预约场次为空，当前阶段为有效线索，跨天后变成暂缓。对照用例把运营消息换成绝对日期和时间，分层可识别预约。 | 日常口语约成的试听会漏统计，也可能漏提醒。企微窗口只记录采集时间，直接用它推算「明天」可能写错日期。 |

| 中 | 本地预览显示新识别的微信号和 85 分，飞书保留了手填值，同步结果只有「更新 1」。 | 手填保护有效。运营从结果无法确认哪些字段已写入、哪些保留了人工值。 |

## 修复复验

用相同的合成会话、本机 Ollama 和原飞书验收表复跑。六条原记录均更新，重复同步均为「已是最新」，表内记录仍为六条。微信 ID、学情和复核备注的手填值均保留。

| 修复 | 复验结果 |
| --- | --- |
| 高中生明确描述持续丢分 | 「函数题容易丢分」进入证据摘要，学习目标为「提高成绩」，线索判为「有效」。 |
| 已约定相对时间但日期不可核实 | 「明天晚上 7 点可以试听」和「好，就约这个时间」同步为「预约时间待确认」。具体场次留空，跨天后仍保持该状态。 |
| 未约线索跨天 | 工作台显示「暂缓」「待更新」。同步原行后，飞书变为「暂缓」，工作台恢复为「已同步」。 |
| 首次采集只有一问一答 | 合成窗口快照新增 2 条，重复采集新增 0 条，完成分层。 |

原行核对结果存于 `.local/ops-acceptance/rerun-results.json`。企微采集使用合成快照，真实企微窗口仍需单独验收。

## 真实企微补验

「点点滴滴」的真实企微窗口两次均读取到同样的 8 条可见文字。首次采集 8 条并完成本机分层，重复采集新增 0 条。从这 8 条中取相邻的运营提问和对方答复，在独立会话回放。首次新增 2 条，重复采集新增 0 条，分层为「资料领取」。飞书验收表新增 1 行，重复同步显示「已是最新」，按线索 ID 回查仍为同一行。完整 8 条仅用于本机验证。证据见 `.local/live-two-turn/result.json`。此用例分别验证了真实窗口读取和两条消息处理。

## 需要确认的业务口径

- 「预约时间待确认」当前保留确认原话，具体场次留空。业务报表是否将它单列为已达成口头预约，待确认。
- 初中线索判为「明确不符合」后，是否继续保留预约阶段和默认跟进状态。用带绝对时间的合成输入验证，规则目前允许初三家长同时出现「明确不符合」「已约试听」「推进中」。
- 客户明确拒绝后主动回来咨询，哪些消息可以重新开启跟进。用合成输入验证，「我重新考虑了，想了解高二数学课程」目前仍保留「拒绝」。
