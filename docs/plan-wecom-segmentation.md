# 企微私聊用户分层首版方案

## 目标与范围

用一个企微成员账号试点。根据该成员与外部联系人的文字私聊，提取高中在线教育招生线索的阶段、学习需求和复核事项，并同步到飞书多维表格。同一联系人持续更新同一行。试点覆盖抖音和小红书自然流线索，缺少渠道依据时显示「未知」。

## 分层规则

将有效线索判定、转化阶段、跟进状态和核实状态分别记录。当前阶段依据仍然成立的事实判断，允许跳阶段。已发生的有效事件保留时间，误判或撤回的证据重新计算。

| 情况 | 首版建议规则 |
| --- | --- |
| 待识别 | 尚无足够证据判断目标学段或学习需求，或只有打招呼和客服单方陈述。 |
| 资料领取 | 客户只索取资料。阶段仍为「待识别」，打上「资料领取」标签，暂不计入有效线索。后续有新证据时重新判定。 |
| 有效线索 | 有高中学段证据，且表达具体学习问题、目标或课程需求。学段可由年级或明确的高中身份支持。 |
| 已约试听 | 客户明确确认试听场次或时间。员工发送试听链接、提议时间或客户只说「周末有空」，均不足以确认预约。 |
| 有报名意向 | 客户明确表示愿意报名、确认报名方案或约定付款时间。单纯问价记为咨询信号。 |
| 到课或付费待核实 | 聊天出现已参加试听或已付款的明确陈述时，分别标记「待核实」。缺少相关信号时字段留空。 |
| 改期、暂缓或明确拒绝 | 写入跟进状态。预约取消时清除当前有效场次，保留有过预约的事实。无响应本身不足以判定拒绝。 |

系统只提取对话中有依据的事实。每次升级保留事件时间和脱敏证据摘要。客户纠正年级、否认已付款等情形触发重新判定。规则区分说话人、引用和否定语境，员工自己的建议或假设不能当作客户承诺。

## 飞书多维表格

| 字段组 | 字段及说明 |
| --- | --- |
| 标识和渠道 | 线索 ID，使用稳定的试点联系人标识。来源为抖音、小红书、其他或未知，保留来源依据。 |
| 当前分层 | 有效线索判定（有效、资料领取、待识别、明确不符合），当前阶段（待识别、有效线索、已约试听、有报名意向），跟进状态。 |
| 学习需求 | 咨询人身份、年级、高考选科组合、学习目标、主要卡点。高考选科仅记录物理、化学、生物、政治、历史、地理中已确定的三门，信息不足时留空。 |
| 时间和里程碑 | 首次纳入时间、首次判定有效时间、首次确认预约时间、当前有效试听场次、最后互动时间。首次纳入时间与实际进线时间有区别，回放数据需单独标识。 |
| 核实和证据 | 到课待核实、付费待核实、证据摘要、证据时间、人工复核备注。聊天全文和附件留在原数据来源。 |

默认视图建议为「全部线索」「有效待约」「试听已约」「到课／付费待核实」。系统更新分层字段，保留飞书里的人工备注。

## 同步与异常处理

1. 先用合成或获准使用的脱敏文字私聊验证。每条消息包含消息标识、联系人标识、时间、说话人和正文。接入存档后沿用相同结构。
2. 以消息标识去重，同一联系人按会话顺序更新。结构化提取年级、需求、预约、报名、到课和付款信号，再由规则计算阶段。消息撤回或新旧证据冲突时重算受影响的字段。
3. 按线索 ID 更新飞书记录，写入成功后记录对应的 `record_id`。新建请求超时后先查同一线索 ID，再决定是否重试。写入失败进入重试队列，重复处理同一批消息只更新原有行，较旧的结果不能覆盖较新的分层。
4. 真机接入前确认两个权限。企微侧确认所属企业是否开通会话存档、试点成员是否在范围内及哪些客户私聊可用。飞书侧确认写入身份的 API 权限和目标表格的编辑权限。

接口参考见 [企微会话内容存档使用前帮助](https://developer.work.weixin.qq.com/document/path/91361) 和 [飞书多维表格新增记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create)。

## 业务指标与验收

- **有效线索率**按同期新进线的去重人数计算，分子为统计窗口内判定有效的人数，分母含待识别和只领资料的人。若试点只覆盖部分私聊，报表标注数据覆盖范围，样本回放仅展示样本结果。
- **试听预约率**用同批有效线索中确认预约的人数除以有效线索人数，并说明观察窗口。试听到课和付费只展示待核实人数。实际试听转化率、付费转化率和 GMV 等可核实数据接入后再统计。
- **分层质量**建议用 40–60 段人工标注的独立会话做首轮验收，覆盖资料领取、学段缺失、学科需求、约课、改期、到课或付款自述和无关语境。建议有效线索精确率和召回率各达到 90%，同时报告各类别样本量与错误案例。合成数据结果仅用于规则验收。
- **同步质量**重复导入、写入超时后重试和迟到消息均不产生重复行，不覆盖人工备注。无到课或付款信号的会话不产生对应待核实项，待核实信号不产生实际成交金额。

### 首批验收用例

| 用例 | 输入或操作 | 预期结果 |
| --- | --- | --- |
| 资料领取 | 客户说「发我一份高二数学资料」后无回复。 | 阶段为待识别，标记资料领取，有效线索数不增加。 |
| 学段待确认 | 客户说「数学跟不上，想找补课」。 | 记录学科和需求，有效线索判定为待识别。 |
| 转为有效 | 同一联系人随后补充「孩子高二」。 | 更新同一行，判定为有效线索。 |
| 确认预约 | 员工问「周六 19 点能上试听吗」，客户回复「可以，就这个时间」。 | 当前阶段更新为已约试听，保存场次。 |
| 取消预约 | 已预约的客户回复「周六去不了了，时间待定」。 | 标记待改期，清除当前场次，保留首次预约时间。 |
| 客户自述 | 客户说「昨天试听了，刚刚也付过款」。 | 分别标记到课和付费待核实，成交金额留空。 |
| 条件句与否定 | 客户说「我还没试听，如果满意我再付款」。 | 到课和付费待核实字段留空。 |
| 写入超时 | 飞书已保存新记录，但客户端超时后重试。 | 重试后同一联系人仍只有一行，人工备注原样保留。 |

## 实施顺序

1. 确认本方案，建立样本、人工标注和分层规则，先验证离线提取和边界用例。
2. 用测试飞书表验证首写、更新、重复导入和失败重试。交付可操作的线索视图。
3. 会话存档确认可用后，从单账号私聊小范围联调，验证采集、分层和同步。存档条件未满足时，用样本完成前两步的验证。
